| N-001 | 🔴 Blocker | `docker-compose.yml` | L348–353 | `unleash-init` provisions 6 flags with **invented names** that do not appear anywhere in the spec, plan.md, data-model.md, or `FeatureFlagPort.java`. Created names: `docai.document.classification.enabled`, `docai.document.extraction.llm.enabled`, `docai.document.fraud.detection.enabled`, `docai.document.ocr.enabled`, `docai.billing.quota.enforcement.enabled`, `docai.pipeline.async.enabled`. **Spec FR-019 mandates exactly**: `billing.enabled`, `fraud.v2.enabled`, `extraction.mistral.enabled`, `dashboard.search.enabled`, `notifications.inapp.enabled`, `maintenance.mode`. T024 validation checks these exact names. The flag names also disagree with `quickstart.md` which correctly lists the 6 spec-mandated names. | Replace the 6 `create_flag` calls with the exact names from FR-019. |
| N-002 | 🔴 Blocker | `docker-compose.yml` | L333–334 | `unleash-init` uses `UNLEASH_TOKEN: "*:*.unleash-insecure-api-token"` — a **frontend client SDK token** — to call the Unleash admin API at `POST /api/admin/projects/default/features`. The Unleash admin API requires an admin-scoped token; client tokens return HTTP 403 Forbidden. The `|| echo "Flag already exists (skipped): $$1"` silences the 403 silently, making the service *appear* to succeed while creating zero flags. FR-019 is therefore still unmet despite the `unleash-init` service being present. | Add `INIT_ADMIN_API_TOKENS: "default:*.unleash-insecure-admin-token"` to the `unleash` service environment (Unleash v5 supports this). | N-003 | 🟡 Warning | `k8s/kustomization.yaml` | All | Adding `kustomization.yaml` to the `k8s/` root directory breaks the T016 validation command `kubectl apply --dry-run=client -f k8s/`. When `kubectl apply -f <dir>` processes a directory, it includes all `.yaml` files — including `kustomization.yaml`. kubectl in `-f` mode does not understand `kustomize.config.k8s.io/v1beta1 / Kustomization` as a native resource and will error: *"no matches for kind 'Kustomization' in version 'kustomize.config.k8s.io/v1beta1'"*. T016 and the `quickstart.md` both reference `kubectl apply --dry-run=client -f k8s/`. | Update T016 and `quickstart.md` to use `kubectl apply --dry-run=client -k k8s/overlays/staging` (using `-k` instead of `-f`). Alternatively move `kustomization.yaml` + overlays to `k8s/base/` and keep `k8s/` as raw manifests only. |
